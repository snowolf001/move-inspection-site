Privacy Policy for LORAN

LORAN — published by Clean Utility Apps

Effective date: August 21, 2026

Overview

LORAN is an English-speaking practice app. The current version includes scenario-based speaking practice, conversation practice, speech transcription, AI-generated replies, correction flows, and audio playback for scenario lines and generated responses.

This Privacy Policy describes the data flows shown by the current LORAN mobile app and TalkFlow backend code as of August 21, 2026. It does not describe planned features that are not active in the current implementation.

Microphone access and voice recordings

LORAN requests microphone permission so you can speak during practice and conversation exercises.

When you record a spoken response, the app creates a local recording on your device and uploads that recording to the LORAN backend for speech-to-text processing. The backend receives the uploaded audio and forwards it to OpenAI for transcription.

The reviewed backend transcription path does not write learner audio recordings into LORAN’s TalkFlow PostgreSQL tables or Cloudflare R2 audio storage as part of normal transcription handling. However, because the audio is transmitted off device for processing, we do not describe learner recordings as device-only data.

Speech transcription

LORAN uses OpenAI speech transcription services to convert your recorded speech into text. The current backend configuration is English-only and is set up to request an English transcript in Latin script.

The transcript is returned to the app and used to continue the active speaking flow, such as submitting a conversation turn or checking a suggested expression against the target sentence.

The reviewed TalkFlow backend code logs transcription request metadata such as file size, duration, and transcript length, but it does not show a TalkFlow database write that stores the full learner transcript as practice history.

Conversation text and AI processing

During conversation practice, the app sends your current scenario ID, release version when applicable, and the conversation message history needed for the turn. User messages are sent to the LORAN backend, which then sends the conversation request to OpenAI to generate the next reply.

During correction and suggested-expression practice, the app sends the text needed for those features, such as user messages, target sentences, and recognized learner text, to the LORAN backend. The backend uses OpenAI to generate correction or feedback output.

Based on the reviewed code, LORAN does not currently create an end-user account-based conversation history database for whole learner chats or whole learner transcripts. The backend does, however, process this text to return AI responses and feedback.

AI-generated replies, text-to-speech, and audio playback

LORAN plays a mix of authored scenario audio and generated audio. Authored scenario audio is served through the LORAN backend using signed playback URLs.

For generated speech, the backend uses OpenAI text-to-speech. The current TTS profile in code uses OpenAI tts-1, voice nova, speed 0.9, MP3 format, and English language settings.

The current backend implementation also stores TTS cache metadata in PostgreSQL and stores generated or published MP3 audio objects in Cloudflare R2 object storage. TTS cache rows include the generated text and normalized text for the cached phrase, along with cache and audio-asset metadata. This means some AI-generated reply text and its corresponding audio may be persisted on the backend for reuse.

What is stored on your device

The current mobile app stores several items locally, including:

  • Voice preference settings
  • Internal release-selection settings used for release testing
  • Cached TTS audio files used for playback reuse
  • Local recording files created while capturing learner speech

The reviewed code explicitly deletes abandoned recording files when a recording session is cancelled. It does not show a general guaranteed deletion pass for every successful recording after transcription.

The current History screens use bundled mock sample data rather than a live server-backed LORAN practice-history service.

Backend storage and retention visible in code

The reviewed TalkFlow backend stores published scenario metadata, published scenario audio metadata, TTS profile records, TTS cache metadata, release records, and audio asset metadata in PostgreSQL.

The reviewed code also stores published scenario audio and cached or published TTS MP3 objects in Cloudflare R2 object storage.

We found explicit logic for deleting stale missing global TTS cache rows when the related object is missing, and for deleting release audio/cache metadata during release-management workflows. We did not find a general user-facing retention schedule for learner recordings, transcripts, or conversation text in the current LORAN implementation.

Technical logs and diagnostic data

The backend logs HTTP request metadata including request ID, endpoint, path, status, elapsed time, query parameters when present, and IP address. TalkFlow-specific backend logs also record technical details such as scenario IDs, message counts, transcript length, cache timing, and TTS timing information.

On the mobile side, the current app includes diagnostic logging for recording state, speech processing, and playback. In development or internal testing modes, the code can retain and log details such as the last learner recording URI, transcript text, transcript errors, metering details, and stop reason.

We did not find a mobile crash-reporting SDK or a mobile analytics SDK actively integrated into the current LORAN app code reviewed here.

Accounts, authentication, advertising, and payments

The current LORAN mobile app does not show a user login or account creation flow for its TalkFlow speaking features. The current backend protects API routes with a shared API key rather than end-user account authentication.

We did not find evidence that the current LORAN mobile implementation serves advertising.

The current closed-testing version does not expose active in-app payment processing to users. The mobile code contains placeholder paywall UI and TODO comments, but we did not find an active purchase SDK or active LORAN billing flow in the code reviewed for this policy.

Third-party service providers identified in the current implementation

  • OpenAI, for conversation generation, correction and expression feedback generation, speech transcription, and text-to-speech
  • Cloudflare R2, for stored audio objects and signed playback URLs
  • PostgreSQL, for LORAN scenario, release, TTS profile, cache, and audio metadata

We did not identify an active mobile advertising SDK, mobile crash reporter, or mobile product-analytics SDK in the current LORAN app code reviewed for this policy.

Your choices

You can choose whether to grant microphone permission. If you do not grant microphone permission, voice speaking features will not work as intended.

You can also stop using the app, delete app data from your device, or uninstall the app. Because some processing happens through the LORAN backend and third-party providers, deleting the app from your device does not by itself guarantee deletion of all server-side technical or cached data that may already exist.

Data deletion requests

If you want to ask about deletion of LORAN-related backend data or have privacy questions, please contact us at the email below. Because the current implementation does not use a normal end-user account system for LORAN, we may need additional information from you to identify any relevant records.

Children’s privacy

LORAN is not designed specifically for children. If you believe a child has provided personal information through LORAN, please contact us so we can review the request.

Security

We use backend infrastructure and third-party services to operate LORAN, but no software or transmission method can be guaranteed to be completely secure. This policy describes the current code-level data flows we reviewed; it does not make promises about perfect security or specific encryption practices beyond what can be directly confirmed in the reviewed code.

Changes to this policy

We may update this Privacy Policy as LORAN changes. When we do, we will update the effective date on this page.
